# Input: sdlc-adopt / legacy-layout-migration

## Initial state

A Python project set up by an older version of these skills, with real code that
has never been annotated. `/sdlc-init` has already run (scaffolding is present,
no steering documents were written — the legacy-layout branch). The user now
runs `/sdlc-adopt`.

This is the flagship adopt case: Mode A (relocate), Mode B (document from code)
and Mode C (annotate) all run, and Mode C edits working source.

## What the skill must work out

- `docs/product.md` and `docs/tech.md` are conclusive legacy markers, so Mode A runs.
- `specs/auth/` uses the retired `requirements.md` + `design.md` pair and must be
  merged into one `spec.md` with a Feature Key.
- `src/auth/session.py` starts with `#!/usr/bin/env python3`; `src/auth/cli.py`
  adds `# -*- coding: utf-8 -*-` on line 2. A header placed above either one
  breaks the file — the shebang stops being line 1, and PEP 263 requires the
  encoding declaration on line 1 or 2.
- `vendor/lib/x.py` and `api/gen/user_pb2.py` are not the project's to annotate.
- The unkeyed `@sdlc REQ-003` must be re-keyed to `@sdlc AUTH:REQ-003`.

## Files the skill reads

`.sdlc/CONVENTIONS.md`, `.sdlc/ANNOTATION.md`, `.sdlc/config.json`,
`.sdlc/templates/spec.md`, `.sdlc/templates/drift-report.md`, the legacy
artifacts above, and every source and test file in scope.
